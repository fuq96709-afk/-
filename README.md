# 续镜 · AI 视频脚本自检器

一个面向 AI 视频、AI 短剧创作者的网页 MVP。在生成视频前检查脚本中的人物、动作、道具、空间、产品用法和剧情因果风险，展示完整修正稿、问题证据与修改说明。

> **项目状态：功能原型，检测质量仍待验证。** 当前采用一次模型调用同时检测与改写。用户实际反馈是检测标准不稳定、容易过度修改；“固定标准、先检测后选择修正”尚未实现。不要把已完成界面和自动化测试理解为审校准确性已经达标。

## 为什么做

脚本有些句子读起来通顺，生成成画面却可能出现手部冲突、道具瞬移、人物错位或动作接不上。工具的目标是提前指出这些风险，减少生成后的返工；检查重点不是语法、文笔或审美评分。

例如：“她左手拿着手机，同时双手抱起箱子。”应指出手部占用冲突，并建议先收好手机。合理的切镜、省略或个人风格不应被当作明确错误。

## 当前功能

| 功能 | 当前行为 |
| --- | --- |
| 六类检查 | 人物连续性、动作连续性、道具连续性、空间逻辑、产品用法、剧情因果 |
| 完整修正稿 | 左侧保留原稿，右侧展示可复制的完整修正稿 |
| 问题列表 | 原文行号、类型、原文证据、具体问题、AI 生成风险、修改建议 |
| 修改说明 | 修改前、修改后、修改原因；引用必须能在原稿和修正稿中找到 |
| 原文定位 | 点击问题或修改说明的行号，选中左侧对应原文 |
| 结果视图 | 完整修正稿／修改说明／问题列表，可用键盘方向键切换标签 |
| 本机历史 | 最近最多 10 次成功检查，支持恢复、单条删除及清空；存储体积过大时可能更少 |
| 接口设置 | DeepSeek、智谱 GLM、Kimi；每个服务分别设置密钥 |
| 状态反馈 | 加载、取消、超时、接口错误、空结果、复制与定位提示 |
| 示例 | 固定演示数据，明确标注，并非实时 AI 检查；不计入真实历史 |

应用自身没有用户系统、登录、支付、数据库或多 Agent 编排。现有 Sites 部署的访问保护属于托管平台，不是应用登录功能。旧 GPT 同步兼容代码使用 R2 对象存储，和首页 API 流程分开，详见下文。

## 使用

1. 点击“试试示例”了解输出，不产生模型调用。
2. 点击右上角“API 模型设置”，选择服务和模型，填写对应 API Key。
3. 粘贴脚本，点击“自检并修正”。
4. 查看完整修正稿、修改理由及原稿问题，人工决定是否采用。
5. 可在“检查历史”中回看此前成功检查。

每次检查仅向选中的服务发送一次模型请求，不自动重试或自动切换服务。调用费用由对应 API 账户承担。模型配置集中在 `src/core.mjs` 的 `PROVIDERS`；这些是代码中保留的选项，不代表所有账户当前都具备访问权限，维护时需核对服务商文档。

**目前仍会自动生成修正稿，尚不支持“勾选问题后仅应用选中的修改”。** 提示词要求保留核心剧情、人物、对白和风格，但这不是代码能保证的语义约束。

## 本地运行

需要 Node.js 22+。无第三方运行时依赖，不需要安装依赖即可运行：

```sh
npm run build
npm start
```

浏览器打开 `http://127.0.0.1:4173/`。

```sh
npm test
```

本地服务只绑定 `127.0.0.1`。修改源码后重新构建并重启服务。不要只双击打开 HTML；真实模型请求需要后端 `/api/check`。

## 最简单的技术结构

```text
浏览器：原稿、API 设置、结果视图、本机历史
                    ↓ POST /api/check
单个 Worker：验证输入 → 调用一个模型 → 验证结果 → 返回 JSON
                    ↓
浏览器：完整修正稿、修改说明、问题定位
```

- 前端：原生 HTML、CSS、JavaScript。
- 后端：Web 标准 Request、Response、fetch；构建为 Worker ESM。
- 本地预览：Node.js HTTP 服务运行同一 Worker。
- 历史：浏览器 localStorage，无跨设备同步。
- 模型：当前接入固定服务商白名单的 Chat Completions 风格接口与 JSON 输出。
- 扩展 GPT／Claude 等服务需要在后端加入服务配置、鉴权及参数适配，当前首页没有这些选项。

## 结果与检查规则

核心输出包含：

- `checkedTypes`：六类检查维度。
- `summary`：结果概述。
- `issues`：原稿行号、逐字引用、类型、问题、风险和建议。
- `revisedScript`：完整修正稿。
- `changes`：实际修改的原文位置、修改前后片段和原因。

问题状态分为 `confirmed`（有证据的问题）与 `needs_confirmation`（待确认）。缺少产品资料时，要求标记具体疑问，不编造品牌参数或厂家使用规则。

提示词吸收了 novel-script 的“一拍一件事、改一拍连读前后、核对人物和道具状态”等审校原则。这是内置提示词规则，并非在服务器上安装或运行一个剧情 Agent，也不是完整短剧写作流水线。

代码校验原文行号、逐字证据、输出字段、长度、修正稿与修改片段等结构。**结构有效不能证明问题判断正确，也不能证明修改保留了全部创作意图。**

## 数据与密钥

- API Key 仅在当前页面内存保存，刷新后清除，不写入历史记录。
- 检查时，脚本和密钥经本站后端发送给选中的模型服务。应用代码不主动持久化首页 API 请求中的脚本或密钥。
- 成功检查的原稿和结果保存在当前浏览器 localStorage；共用浏览器的人可能看到，清除网站数据后会丢失。
- 脚本不会因 GitHub 源码备份而从用户浏览器上传到仓库。
- 上游模型服务的数据政策和计费规则仍然适用。

## 已知问题与下一步

1. **检测标准不稳定**：依赖模型判断，存在误报、漏报、反复提出新修改的风险。
2. **检测与改写绑定**：点一次就返回完整修正稿；用户希望先确认问题，再决定修改范围。
3. **API 配置门槛**：当前首页要求使用者自行填写 Key；没有免配置的后台模型供应方案。
4. **文字检查的边界**：不读取实际生成的视频，无法诊断真实画面的动作异常，也不保证减少错码。
5. **模型配置会过期**：服务商调整模型名、参数或权限后需要维护。

详细的判断标准和验收方向见 [产品复盘与改进方向](docs/PRODUCT_REVIEW.md)。这些是待实施方案，未混入“已完成功能”。

## 测试与限制

自动化测试覆盖证据定位、结果校验、模型白名单和参数、错误与取消、历史读写、旧 MCP 桥接与同步隔离。测试使用模拟响应和模拟存储，不能替代真实 API 联调或审校质量评测。

当前输入上限 16,000 字符，每次最多 20 个问题、40 条修改说明，完整修正稿最多 32,000 字符。后台模型请求超时约 90 秒。长脚本或长输出仍可能截断或被校验拒绝；失败不会显示部分结果冒充完整修正稿。

## 旧 GPT 同步兼容代码

`/mcp`、`/app-preview`、`/api/sync` 保留在代码中，首页已隐藏 GPT 模式入口并默认走 API。它们需要平台可信用户身份、宿主桥接及可选 R2 `BUCKET`，本地预览未提供这些环境。

旧同步设计为每个账户暂存当前一份任务：逻辑有效期 24 小时，过期访问时清除，非后台定时物理删除。构建与模拟测试通过不代表与真实 GPT 对话的自动同页联动已经验证；不能把这些路由当作首页已实现“直接调用当前 GPT”的证据。

## 部署与备份

`npm run build` 输出 `dist/server/index.js`，需要能运行 Worker ESM 的环境，不能当作纯静态站点直接部署。旧平台的身份头、R2 绑定及 MCP 发现需要按目标平台单独配置，不能信任任意客户端伪造的用户身份头。

GitHub 备份仅含源代码、测试和文档，不含 API 密钥、用户脚本历史、Git 历史凭据或原 Sites 项目标识。在线网站的发布和 GitHub 源码上传是两个独立操作。
