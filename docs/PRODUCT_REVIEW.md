# 产品复盘与改进方向

这份文档记录当前原型与用户需求之间的差距，作为后续开发依据。以下改进尚未实施。

## 核心需求

在生成 AI 视频前，找出会造成动作冲突、道具跳变、人物错位、镜头衔接失败的脚本问题。尽量保留核心剧情、人物关系、对白、风格与结局，只对有依据的问题提出最小修改。

## 当前原型的问题

### 1. 检测没有稳定标准

用户反馈：无论放入什么脚本，系统都会找到理由修改。这让用户还要检查“修改是否合理”，增加了工作量。

当前提示词虽要求保留原意，代码也校验引用与位置，但这些无法保证模型没有把合理省略、正常切镜或审美偏好误判为错误。功能测试通过不等于产品检测有效。

### 2. 使用需要 API 配置

用户期望打开工具就能检查并看到完整结果。目前首页需要填写 DeepSeek、智谱或 Kimi 的 API Key。旧 GPT 跳转／回写方案增加步骤，也没有验证实现稳定的一键同页体验。

不能把“隐藏 Key 输入框”描述为不再需要模型服务或不再产生费用。后台供应模型、谁承担费用、如何授权和限制调用，仍需确定。

## 拟定的检测标准

| 结论 | 必要依据 | 处理 |
| --- | --- | --- |
| 明确错误 | 同一连续状态中存在原文可定位的冲突；已排除换场、倒叙等合理解释 | 展示前后证据及局部修正供选择 |
| 待确认 | 有具体疑问，但上下文不足，存在合理解释 | 提问或标注，默认不改写原稿 |
| 通过 | 没有足够错误证据，或变化已有合理交代 | 明确通过，原稿不变 |
| 可选生成建议 | 动作密集或精确交互可能较难生成，但并不构成脚本矛盾 | 与明确错误分开，默认不应用 |

六类检查维度保持不变。禁止为了每类都有问题而凑数；禁止把“没有写清所有细节”直接等同于错误；不增加审美评分或强制短剧模板。

## 拟定流程

1. 粘贴原稿，先检测，不生成整篇改写。
2. 展示证据、判断标准、风险与局部建议。
3. 用户选择接受哪些修正。
4. 只应用选中的修改，其他内容逐字保留；未选择时不改稿。
5. 对受影响的前后动作再核对，防止修一处引入新矛盾。

“只应用选中修改”需要可校验的局部替换或补丁，不能只要求模型口头承诺不改其他地方。

## 建议的质量验收

准备一组由创作者确认答案的脚本样本，至少覆盖：

- 左手握杯又双手搬箱子的明确冲突。
- 切镜或明确时间跳跃后的合理换位，不误报为瞬移。
- 人物自身左右与画面左右不同，不误报为换手。
- 正常拿取和放下的隐含过程，不要求机械补写所有步骤。
- 产品说明缺失时只标具体待确认项，不编造功能结论。
- 超现实或幻想设定下合理成立的动作，不按日常物理规则强改。
- 已经正确的脚本，返回通过，原稿保持不变。
- 只接受一处修改时，其余内容逐字保持。

记录误报、漏报、用户接受比例，以及同一份合格稿反复检查时是否不断产生新的修改。测试集不能只有刻意错误的示例，也不能把模型自己的输出当作唯一标准。

## 模型接入的待决策项

- 是否继续保留独立网页。
- 是否由维护者在后台供应模型，用户无需填写 Key。
- 调用费用、额度、访问授权与滥用限制由谁负责。
- 如果继续保留用户 Key，是否仅作为高级可选模式。

在实际联调确认前，不宣称已经实现调用当前 GPT 聊天账号或订阅来为独立网页自动生成结果。

## 开发优先级

1. 先建立创作者认可的判定样本和明确标准。
2. 拆开检测与改写，落实原文保护和选择性修改。
3. 再降低模型接入门槛。
4. 最后根据真实使用反馈优化界面。
